# 2차 개선 기능 구현·안전 배포 체크리스트 (2026-10-20)

> 상태: **PR #5 초안 / 운영 배포 보류.** 본 문서는 2차 개선 브랜치에 한정한다.

## 사용자 확정 범위
1. 신규 예약의 모니터링 진행 장소: 120자 이하 자유 입력 필수. 기존 예약의 NULL 장소 허용.
2. 관리자 예약 정보의 장소 조회·단독 수정 및 변경 이력. 예약 장소와 실제 점검 장소 별개 저장.
3. 관리자 로그인 → 예약 관리 → 결과관리 목록 → 동아리 상세: 브라우저 뒤로/앞으로 경로 처리, 인증 확인.
4. 작성 완료된 결과의 수정 모드. 수정 완료 후에도 completed 상태와 최초 완료시각 보존.
5. 현황 카드 다섯 개를 클릭할 수 있는 필터로 변경 (전체/미작성/작성 중/완료/미실시). 유형·검색 연동.
6. 결과 기록 소프트 삭제/복구. 사진 바이너리 및 모든 예약은 보존. 삭제된 기록은 미작성으로 집계, 동아리 선택 시 복구 가능 안내.

## 브랜치 변경 파일
- `src/main.js`: 예약 장소 입력/확인/상세/관리자 장소 수정, History API 기반 관리자 메뉴 이동.
- `src/reports.js`: 클릭 카드, 작성완료 수정, 취소 시 사진 교체 미실행, 삭제/복구, 실제 점검장소 초깃값.
- `src/reports.css`: 카드 키보드 포커스 및 상태 강조, 완료 기록의 읽기 전용 필드.
- `supabase/functions/monitoring-api/index.ts`: 예약 장소 서버 검증 및 신규 location-aware RPC 조회/호출.
- `supabase/functions/monitoring-reports/index.ts`: 삭제·복구 API, 보고서 완료시각 보존, 삭제된 사진 API 차단.
- `supabase/migrations/202610200005_reservation_location_and_soft_delete.sql`: **준비 완료, 실제 적용 안 됨.** 신규 컬럼·장소 변경 이력·예약 RPC·보고서 삭제/복구 필드.
- `tests/monitoring-workflow.test.mjs`: 동아리 분류, 입력, History API, 필터, 편집, 삭제 정적 회귀 테스트.

## 배포 절차 (최종 승인 이후만)
1. GitHub main 및 Supabase DB 사전 스냅샷 확보: 예약, 차단, 결과, 사진 목록·버킷 상태. 원본 사진을 별도로 백업하는 방법도 사전 확보.
2. SQL 마이그레이션을 운영에 적용하기 전 별도 테스트 DB에서 스키마·함수/권한 적용 검증.
3. 사용자와 일정 협의 후 `202610200005...` 마이그레이션 적용. 기존 예약자는 reservation_location=NULL 유지.
4. 기존 기능을 유지한 `monitoring-api` 새 코드를 Edge Function으로 배포 → 관리자 인증, 예약 생성/변경/취소/차단 기능 재검증.
5. `monitoring-reports` 새 코드를 별도 Edge Function으로 배포 → group 권한, soft delete/recover, 완료 수정, 기존 사진 저장/교체 검증.
6. 사용자 실기기 확인(PC Chrome/Edge, Android Chrome, iPhone Safari) 후에만 PR #5 main 병합.
7. Github Pages 반영 확인 후 확인해야 할 사항을 담당자에게 공유. 문제가 있으면 프런트엔드만 이전 커밋으로 롤백하되 DB/Storage 데이터는 **삭제하지 않는다**.

## 배포 차단 조건
- 기존 예약 정보 또는 결과/사진이 줄어들면 즉시 중단.
- 새 예약의 장소 미입력 허용, 또는 기존 예약의 NULL을 강제 변경하면 중단.
- 관리자 이외의 그룹이 예약 장소나 결과를 수정/복구/삭제 가능하면 중단.
- 브라우저 뒤로 가기 중 결과 미저장 내용 또는 업로드 중 사진이 소실되면 중단.
- 완료 기록 수정 후 완료 상태가 해제되면 중단.
- 사진이 2장 저장되거나 교체 중 기존 사진이 먼저 삭제되면 중단.
- 삭제 기록 복구 뒤 내용/사진이 빠지면 중단.

## 예상 테스트 시나리오
### 예약
- 일반 학생 장소 입력(한글/괄호/호수), 공백 오류, 120자 초과, 중복 시간 충돌, 예약 내용 최종 확인.
- 기존 장소 미입력 예약 조회, 관리자 장소만 변경, 예약 날짜/시간 그대로 유지, 위치 변경 이력 기록.
- 일정 변경·취소, 시간 차단 및 하루 전체 차단의 회귀 테스트.

### 관리자 내비게이션
- 관리자 로그인 후 #admin → #reports → #report/club-id → 뒤로 #reports → 뒤로 #admin → 뒤로 #home.
- 브라우저 앞으로 가기 #admin → #reports → 기록 상세, 직접 딥링크 접속 시 인증 없는 상태 보호.
- 관리자 예약 모달에서 브라우저 뒤로 시 모달을 닫고 현재 페이지 유지.
- 미저장 편집/사진 업로드 도중 브라우저 뒤로 시 경고 또는 저장 실패로 이동 거절.

### 결과 기록
- 65/16 권한별 카드 수·대상 범위 확인, 작성 완료 카드 필터, 유형/검색 조합, 0개 표기.
- 작성 완료를 수정하고 완료 상태·원래 completed_at 유지, 수정 취소 후 서버 원본 그대로.
- 사진 1장 선택 후 수정 취소 → 기존 사진 유지; 수정 저장 후 서버 저장·교체.
- 작성 중/완료 삭제, 수치 미작성 반영, 복구, 사진과 예약 기록 보존, 다른 그룹 요청 차단.
- 동시 수정 시 보고서 version 충돌 보호.
