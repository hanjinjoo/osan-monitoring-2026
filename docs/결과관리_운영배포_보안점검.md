# 오산대학교 2026-2학기 동아리 결과관리 — 배포 점검 기록

## 확정 범위

- 전체 예약 88개 유지. 결과관리 대상: 전공 혁신 36 + 취업 19 + 창업 16 + 일반 10 = **81개**.
- 전공 부트캠프 5개·앵커_신산업 2개는 결과관리 대상 제외. 창업 '앵커'는 전체 포함.
- **동아리당 완료된 현장 증빙사진 정확히 1장.** 카메라 촬영 또는 갤러리에서 1장 선택, 기존 사진은 새 파일 전송·원자적 DB 전환 성공 전까지 보존.
- 진행 중/미실시 기록은 사진이 없어도 임시 저장 가능. 작성 완료 시 서버에서 사진 정확히 1장 요구.
- PDF/HWP 출력은 구현 범위에서 제외.

  1. `202610200001_monitoring_reports.sql`: 결과관리 전용 테이블 4개, scope 81개, private Storage bucket

  4. `202610200004_staff_login_rate_limit.sql`: 기존 담당자 사번 로그인 시도 횟수 제한(10분간 20회)
- 두 Edge Function 실행:
  - `monitoring-api` v9: 기존 예약 RPC 불변, 로그인 시도 제한 추가
  - `monitoring-reports` v3: 자체 HMAC 인증, 대상 그룹 검증, 임시저장·완료·미실시·사진 첨부
- `monitoring-report-photos` bucket **비공개**, 보고서 테이블 RLS 활성화. `anon` / `authenticated` 직접 읽기 권한 없음. service_role은 서버에서만 사용.
- 텍스트·사진 연결 및 교체 DB 트랜잭션 테스트 후 모두 `ROLLBACK`; 기존 사진 1장 + 신규 pending 1장 상태에서 교체 후 ready 1장만 남음을 확인.
- 외부 무인증 / 위조 토큰 401 차단, 기존 예약 API 공개 state 기능, JavaScript 회귀 검사 및 Deno 타입 검증 통과.
- 사진 업로드는 공식 Supabase Storage TUS 방식(`createSignedUploadUrl` + `x-signature`)을 사용.
  - https://supabase.com/docs/guides/storage/uploads/resumable-uploads

## 사진 화질 및 무료 플랜 정책

- 사진은 **원본 파일 바이트 그대로** 전송하며 무조건 작은 이미지로 다운스케일하지 않음.
- 증빙 사진은 81장(동아리당 1장)으로 설계. 현재 50MB(십진) 한 장 한도, 전체 결과관리 사진 서버 소프트 한도 약 **850MB**.
- 예상 용량: 81장 × 3MB = 243MB / × 5MB = 405MB / × 8MB = 648MB / × 10MB = 810MB.
- Supabase Free 1GB 한도 내에서 다른 Storage 사용량과 미완료 업로드 여유를 확보. 한도 도달 시 업로드를 거절하고 기존 저장 사진은 삭제하지 않음.
- Free에서는 Supabase 원격 이미지 변환이 지원되지 않으므로, 한 장의 고화질 사진을 브라우저에서 크기 조절해 표시. 별도 썸네일 생성은 운영 시 추후 검토.
- HEIC/HEIF 원본 업로드는 허용하지만 브라우저마다 미리보기가 다를 수 있어 모바일 실기기 확인 필요.

## 운영 반영 전후 검증 기준

- GitHub PR #2는 별도 개발 브랜치. 병합 전 자동 테스트 통과와 운영 DB·Storage의 사진 수 확인 필수.
- Android Chrome / iOS Safari: 카메라 직접 촬영, 갤러리 한 장 선택, 파일별 1MB / 10MB 이상 업로드.
- 원본 사진 업로드 실패 시 기존 ready 사진 보존. 새 파일 서버 저장 후 기존 파일 교체. 재접속 후 1장만 표시.
- 업로드 도중 네트워크 오류 시 재시도/실패 파일 정리. 교체 시 old 파일 삭제에 실패하면 관리자 로그에 경고, 이전 Storage 오브젝트 사후 정리.
- 다른 관리 그룹 및 비로그인 사용자의 사진 조회 차단.
- 기존 예약 생성·수정·취소·시간 차단·일괄 차단 기능에 회귀 없음.
- 동아리 대표·지도교수 개인정보는 공개 GitHub에 업로드하지 않음. 교수·학생 이름의 자동 채움은 아직 적용되지 않음.
- 결과 작성/사진 변경은 2시간 인증 세션 만료 시 재로그인이 필요함.
- 실제 직원 사번 및 session token을 사용자 메시지·GitHub Issue/PR·로그에 올리지 말 것.

## 알려진 운영 전 확인 사항

- **실제 관리자 인증을 이용한 사진 실물 TUS 업로드·조회·교체·삭제 E2E 및 Android/iPhone 실기기 시험은 아직 진행되지 않았습니다.** 정적·SQL·무인증 검사와 분리해서 기록할 것.
- 기존 사번 인증은 IP 기반 제한만 추가한 것으로 별도 MFA가 없고, 완전한 공격 방어를 보장하지 않음.
- 1장 용량이 크면 모바일에서 원본 미리보기 로딩이 느릴 수 있음. HEIC 지원은 모바일 브라우저마다 다름.
- Storage 서명 URL 유효기간은 10분, 다시 열기 동작은 API에서 새 URL을 발행함.
- 학교의 사진 촬영·보존·삭제 개인정보 운영 정책 확인 필요.
- 테스트 기록이 없었던 초기 상태라도 실제 데이터가 생성된 뒤에는 임의로 보고서·사진 테이블을 DROP하지 말 것.
